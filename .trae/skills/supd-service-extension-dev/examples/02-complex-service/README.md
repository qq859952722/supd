# 服务名称与版本

- 服务名称：`tcp-app`
- 版本：`1.0.0`
- 用途：提供带 TCP 就绪检测和二进制目录布局的应用服务示例。

# 目录结构与权限边界

- `service.yaml` 由管理员或 supd 管理。
- `bin/myapp` 是服务主程序，`bin/` 中的文件应由管理员维护，服务用户仅可读取和执行。
- `data/` 应保存服务配置与运行数据，服务用户可读写；不得赋予其修改 `bin/` 或扩展脚本的权限。

# 启动方式与就绪检测

部署后 supd 按 `./bin/myapp --port=8080` 启动服务。supd 连接 TCP 端口 `8080` 确认服务已就绪。

# 配置与环境变量

此示例未定义必需环境变量。部署时在 `env.yaml` 的 `env:` 下声明非敏感配置。敏感变量只能列出名称和用途，例如 `DATABASE_PASSWORD` 用于数据库认证，不能写入其值。

# 服务级扩展与 Actions

此示例没有服务级扩展和 actions。可在 `extensions/` 目录添加维护或更新扩展，并在此处说明可执行 actions。

# 数据持久化与升级更新

将持久化配置和状态放入 `data/`。升级时仅替换 `bin/` 中的程序，保留 `data/`；升级前完成备份，验证失败时恢复上一版本程序。

# 常用运维操作

使用 supd CLI 操作：`supd start tcp-app`、`supd stop tcp-app`、`supd restart tcp-app`。通过 `supd logs tcp-app` 查看服务日志。

# 安全与备份注意事项

服务使用最小所需权限运行，不在 README、配置仓库或日志中保存真实密码、token、私钥和运行期敏感数据。定期备份 `data/` 中的持久化配置与业务数据。
