# 服务概述

`tcp-app` 版本 `1.0.0`，演示自动启动、命令参数和 TCP 就绪检测的二进制服务布局。

# 运行逻辑

supd 执行 `bin/myapp` 并传入 `--port=8080`；应用应持续监听该 TCP 端口。

# 目录结构与权限边界

`service.yaml` 由管理员维护；`bin/myapp` 只读执行；持久化配置与状态应放入服务用户可写的 `data/`，服务用户不应修改 `bin/`。

# 启动方式与就绪检测

服务配置为自动启动，命令是 `./bin/myapp --port=8080`，工作目录使用服务默认目录。supd 成功连接 TCP 端口 `8080` 后判定就绪。

# 配置与环境变量

示例没有 `env.yaml` 或必需环境变量；端口直接由命令参数和 readiness 配置指定，修改时须保持两处一致。

# 开发与上游资源

`bin/myapp` 是示例占位程序；本示例未声明上游项目、源码仓库或下载链接。

# 服务级扩展与 Actions

此示例没有服务级扩展和 Actions。

# 数据持久化与升级更新

将持久化内容放入 `data/`。升级时替换 `bin/myapp` 并保留 `data/`；验证失败时恢复上一版本程序。

# 部署与特别注意事项

部署目录名须与 `name: tcp-app` 一致，目标程序必须可执行并接受 `--port=8080`。若替换为真实二进制，部署前确认架构和 libc 兼容性。

# 常用运维操作

使用 `supd start tcp-app`、`supd stop tcp-app`、`supd restart tcp-app` 管理服务，使用 `supd logs tcp-app` 查看日志。

# 安全与备份注意事项

按最小权限运行，不在 README、配置或日志中保存密码、token、私钥。升级前备份 `data/` 中的持久化内容。
