## 会话一：clear-failed 状态重置由 pending 改为 down

### 触发原因

用户报告远程实例 `http://192.168.31.188:7979/` 上的 `code-server` 服务一直显示"等待中"（pending），询问它在等什么。

### 诊断过程

通过远程 supd 的 HTTP API 查询，定位完整因果链：

1. **进程启动失败（根因，非本次修复范围）**：code-server 4.130.0 的 `argon2` 原生模块加载时报 `Error loading shared library ld-linux-x86-64.so.2: No such file or directory`，`ERR_DLOPEN_FAILED`，exit_code=1。宿主机疑似 Alpine（musl libc），glibc 编译的 code-server 无法运行。
2. **重试耗尽**：按退避策略（1s→2s→4s→8s→16s）重启 5 次全部 exit(1)，触发 `max_retries`，状态 `up → failed`。
3. **clear-failed 重置回 pending**：10 秒后 `admin_reset` 事件把 `failed → pending`。
4. **卡死在 pending**：`ClearFailedState`（[internal/api/service_operator.go:689](file:///home/qq/Documents/trae_projects/supd/internal/api/service_operator.go#L689)）仅调用 `sm.ResetTo(core.StatePending)`，不触发启动，也不重算依赖图。而 `pending → starting` 只由 `depends_ready`（上游依赖就绪）或 bootstrap 推进；code-server 的 `depends_on` 为空，没有上游，依赖协调器 `OnServiceDependable` 永远不会遍历到它。结果：无依赖服务永久卡在 pending，等一个不会自动到来的信号。

### 关键代码定位

- `ClearFailedState` 实现：[internal/api/service_operator.go:689-710](file:///home/qq/Documents/trae_projects/supd/internal/api/service_operator.go#L689-L710) — 只 `ResetTo(pending)`，不启动。
- `ResetTo` 绕过状态机转移规则：[internal/core/state_machine.go:144](file:///home/qq/Documents/trae_projects/supd/internal/core/state_machine.go#L144) — 只存状态 + 发 `admin_reset` 事件。
- 依赖协调器只在"上游变可依赖"时拉起下游：[internal/core/dependency.go:42-49](file:///home/qq/Documents/trae_projects/supd/internal/core/dependency.go#L42-L49) — `OnServiceDependable` 只遍历 `GetDependents(上游)`。
- 手动 Start 入口对 pending/down 的分支处理：[internal/api/service_operator.go:194-199](file:///home/qq/Documents/trae_projects/supd/internal/api/service_operator.go#L194-L199)（pending 走 `EventDependsReady`，down/failed 走 `EventManualStart`）。

### 修复方案

规格 §2.8.1（[需求规格说明_v1.5.md:1275](file:///home/qq/Documents/trae_projects/supd/docs/需求规格说明_v1.5.md#L1275)）明确允许 clear-failed "重置为 down/pending"。改为重置为 `down`：

- `down` 可由用户通过 `manual_start` 直接启动（状态机规则 `StateDown → StateStarting`，[state_machine.go:76](file:///home/qq/Documents/trae_projects/supd/internal/core/state_machine.go#L76)），语义明确为"已停止"，避免 pending"等待中"假象。
- 不触发自动启动，符合 `autostart` 仅控制 supd 启动时初始行为的规格约定（§2.8.1 L894-898）。
