## tracker-updater 空行分组修复

### 触发原因

用户反馈：transmission 的 tracker-updater 扩展更新 trackerlist 时擅自删除空行，而空行代表服务器分组，是有意义的。要求找其他热门还在更新的 list，和 adysec 源合并去重后使用。

### 调研发现

**adysec/tracker（原数据源）**：`trackers_best.txt`，364 个 tracker，**扁平列表无空行分组**，包含 7 个 wss://（Transmission 不支持）。

**newtrackon.com/api/all（新数据源）**：持续更新，261 个 tracker，**每个 tracker 之间用空行分隔**（每个 tracker 独立成 tier），无 wss。

**ngosang/trackerslist（经典源，2023 停更）**：trackers_best.txt，20 个 tracker，同样用空行分隔每个 tracker。

**Transmission default_trackers 格式语义**：空行分隔 tier，每个 tracker 独立成 tier 时 Transmission 会并发联系所有 tracker，最大化发现 peer 的机会。这是行业惯例。

### 修复内容（v1.1.1 → v1.2.0）

1. **多数据源合并**：新增 `newtrackon.com/api/all` 作为主源（持续更新、有空行分组），保留 `adysec/tracker` 作为副源（量大）。
2. **保留空行分组结构**：输出格式改为 `trackers.join('\n\n')`，每个 tracker 之间用空行分隔，符合 Transmission tier 语义。
3. **跨源去重**：大小写不敏感去重，避免重复 tracker。
4. **协议白名单过滤**：仅保留 http/https/udp，跳过 wss/ws/i2p（Transmission 不支持）。

### 关键技术点

- **Transmission RPC 字段名**：session-set 请求用 `default_trackers`（下划线），session-get 返回 `default-trackers`（连字符），两者指向同一字段。
- **空行分组语义**：Transmission 的 `default-trackers` 字段用空行分隔 tier，每个 tier 内的 tracker 是同级的；"每 tracker 独立成 tier"让 Transmission 并发联系所有 tracker。
- **newtrackon.com 持续更新**：每 6 小时更新一次，API 端点 `https://newtrackon.com/api/all` 返回纯文本格式。

### 验证结果

- 合并 2 个源，去重后保留 **561 个 tracker**（http×214 https×90 udp×257）
- 含 **560 个空行分组**（每 tracker 之间一个空行）
- 跳过不支持协议 7 个（wss×7）
- 通过 RPC session-get 验证 `default-trackers` 字段实际内容：1121 行（561 tracker + 560 空行），格式正确
- 扩展版本升级至 1.2.0

### 修改的远程文件

- `services/transmission/extensions/tracker-updater/meta.yaml`（version 1.1.1 → 1.2.0，描述更新）
- `services/transmission/extensions/tracker-updater/run.js`（重写数据源获取和合并逻辑）

## transmission-updater v1.1.0 + pre-start-fixperms v1.1.0

### 触发原因

将 transmission-updater 改为 uid 1000 运行后，发现两个问题：
1. **路径 bug**：`getCurrentVersion()` 检查 `serviceDir/transmission-daemon`，但二进制实际在 `bin/transmission-daemon`（与 service.yaml command 一致）
2. **chown 需要 root**：`setupDirectories()` 调用 `chownRecursive(serviceDir, 65534, 65534)`，uid 1000 无权 chown

### 修复内容

**transmission-updater v1.0.0 → v1.1.0**：
1. 修复二进制路径：`${serviceDir}/transmission-daemon` → `${serviceDir}/bin/transmission-daemon`（3 处：stat、runCmd、installBinary targetPath）
2. installBinary 增加 `tjs.makeDir(\`${serviceDir}/bin\`)` 确保目录存在
3. chownRecursive 改为非致命：失败时不再终止流程，依赖 pre-start-fixperms 修复权限
4. `run_as_uid: 1000` + `run_as_gid: 1000`

**pre-start-fixperms v1.0.0 → v1.1.0**：
1. 新增：`chown -R 1000:1000 $SVCDIR/bin $SVCDIR/web`（供 transmission-updater uid 1000 写入）
2. `chmod -R u=rwX,g=rwX,o=rX` 确保 nobody 主进程可读/执行
3. 权限分层：config/→nobody（服务写入），bin/+web/→uid1000（扩展写入），下载目录→nobody

### 关键技术点

- **tjs Direct Sockets API**：`new UDPSocket({remoteAddress, remotePort})` → `.opened` 返回 `{readable, writable}`，写入 `{data: Uint8Array}`，读取得到 `{data, remoteAddress, remotePort}`
- **BEP-15 UDP CONNECT**：16 字节请求（magic 8B + action 4B + tid 4B），16 字节响应（action + tid + connection_id），校验 transaction_id 匹配即存活
- **Transmission tier 语义**：空行分隔 tier，同 tier 内 tracker 并发联系；优质 tracker 独立成 tier 置顶 → 优先被联系
- **uid 1000 权限模型**：pre-start-fixperms(root) 分层 chown：config/→nobody, bin/+web/→1000, nobody 通过 o=rX 读执行

- transmission-updater check-update 以 uid 1000 运行：当前版本 v4.1.3 = 最新版本 v4.1.3 ✓
