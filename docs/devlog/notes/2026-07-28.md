## 关键技术点

- **NSpid 精确映射**：`/proc/<host-pid>/status` 的 `NSpid:` 行最后一项是最内层 namespace PID，可用于精确匹配容器内进程
- **CPU 批量采样**：降级路径先收集整棵树 host PID，批量 `getProcess` 预热基线，统一 `sleep 200ms` 一次，避免逐进程等待
- **curl 流式落盘**：`curl --fail --location --silent --show-error --output <dest>.part` 直接写文件，成功后 `tjs.rename` 原子替换，不经过 JS 内存缓冲
- **按需依赖检查**：curl 仅下载时需要，tar/unzip 仅 WASM fallback 时需要，uname 仅架构探测最后 fallback 时需要；不启动时统一检查
- **nil 防御最小化**：`buildStopConfigs` 返回已初始化空 map，下游 `ShutdownCoordinator` 对缺失配置回退默认 10s/60s

#### WASM 工具调研结论

经全面搜索，**WASI (wasi_snapshot_preview1) 兼容的现成 WASM 工具极其有限**：
- 大部分 WASM 工具（7z-wasm、jq-wasm npm 包等）使用 Emscripten 编译，需要 JS glue 层，**不兼容 tjs:wasi**
- 后续复核确认原调研不完整：`jq-wasi` Release 只有 libjq 静态库，不是可执行 CLI；历史外部实例上传过 `7zz.wasm`，但仓库没有该成品或可复现来源
- 最终选择固定来源、宽松许可证并可直接执行的 `zstd.wasm` 和 `bsdtar.wasm`，详见本文件后续“WASI 成品落地与调用修复”

在 Skill 文档 `06_tjs_runtime_guide.md` 新增 §11 WASM 工具使用指南，内容包含：
- WASM 调用模板（tjs:wasi + WebAssembly.instantiate）
- 可用/不适用 WASM 工具表
- 自编译 WASI 工具指南（wasi-sdk 安装与编译）
- WASM 文件部署方式（构建时内置 / 运行时上传 / 直接复制）
- WASM 调用注意事项

#### Debian slim 镜像变体

新增 `Dockerfile.debian`，基于 `debian:bookworm-slim`：
- 三阶段构建与 Alpine 版结构一致（web-builder → go-builder → runtime）
- tjs 在 Debian 容器中编译（glibc 链接），与 Alpine 版（musl 链接）不互通
- 完整对应 Alpine 工具集（关键包名差异：7zip→7zip/7zz, xz→xz-utils, iputils→iputils-ping, bind-tools→bind9-utils, procps-ng→procps, shadow→passwd, libffi→libffi8, libstdc++→libstdc++6, libgcc→libgcc-s1, dropbear→dropbear-bin）

CI 改造：

- `build-push.yml`：新增 variant 选择参数（alpine/debian/both），拆分 Alpine/Debian 两个构建链 + manifest 合并

标签策略：
- Alpine：latest + vX.Y.Z（不变）

### 关键技术点

- **tjs v26.6.0 proc.wait() 返回值**：`{exit_status: number|null, term_signal: number|null}`，**不是** Node.js 风格的 `exitCode`。误用 `status.exitCode` 会得到 `undefined`，配合 `?? 0` 后变为 0，将所有失败误判为成功 — 这是 F3/F5 修复的核心
- **tjs v26.6.0 无 Buffer 全局对象**：txiki.js 不实现 Node.js Buffer API；流式拼接应用 `TextDecoder` 累加或 `Uint8Array` 直接拼接
- **supd 扩展 action 注入机制**：通过 `SUPD_ACTION` 环境变量传递，非 CLI 参数；`SUPD_SERVICE_DIR` 自动注入给服务级扩展；全局扩展无此变量
- **bsdtar WASM 平台限制**：WASI 不支持 `archive_read_disk`，bsdtar.wasm 仅能列出/解包归档，不能创建归档。supd 扩展使用场景（解压远端归档）正好匹配此能力
- **服务级扩展 entry 路径校验**：meta.yaml 中 `entry` 不允许含 `./` 前缀，否则触发 "contains redundant path components" 配置错误

### 关键技术点

- **三种传参渠道梳理**：`Action.Args`（meta.yaml 写死 CLI 参数，死代码）、`SUPD_ACTION`（supd 自动注入环境变量，实际使用）、`env.yaml`（用户环境变量，前端 EnvTab 管理）。删除 Action.Args 后统一为 SUPD_ACTION + env.yaml 两渠道
- **TempEnv 覆盖顺序**：`os.Environ → mergedEnv（4层 env.yaml）→ TempEnv（用户临时）→ supdEnv（SUPD_*）`。TempEnv 追加在 mergedEnv 之后，executor 中 supdEnv 在最后追加，确保 TempEnv 能覆盖 env.yaml 同名变量但不能覆盖 SUPD_* 保护变量
- **抽屉非阻塞设计**：Drawer 组件点击外部不关闭，需明确按钮操作（保存/运行/关闭），符合用户偏好"非阻塞浮层通知"
- **复用 env-yaml 工具库**：抽屉直接复用 `parseEnvYaml`/`serializeEnvYaml`/`isSensitiveKey`，零后端改动（用现有 `/api/files` 端点读写 env.yaml）
