# 2026-07-25 E2E测试验证与版本发布

## 触发原因
完成代码审计及功能实现后，需要实施真实的运行状态测试（E2E 测试），涵盖前序任务所修改的底层机制并发布。

## 完成要点
- **测试用例修正**：修复了测试验证脚本由于提取服务状态JSON不正确（`state`变为`status`）导致测试无法通过的问题；修复了测试服务配置文件（`restart.policy` 替代 `restart_policy.policy`）使得预期的 `on-failure` 能够正常执行。
- **运行状态 E2E 验证成功**：
  - 测试1：**资源收集** (`Resource Collector`) 成功收集到带有 DFS 子进程的进程树。
  - 测试2：**重启策略与正常退出机制** (`Normal Exit State Machine`) 测试正常以 Exit Code 0 退出后正确进入 `Down` 状态不再无限重启。
  - 测试3：**扩展日志系统注入** (`Executor Logging`) 在运行期间准确捕获 `run_id` 标志并存入 Slog。
  - 测试4：**扩展回退机制更新** (`Extension Updater`) `transmission-updater` 纯JS与WASM在真实 `supd` 环境下自动回退降级顺利完成触发。
- **发布 v0.0.22**：将相关文档（`README.md`, `session-notes.md`）中的版本号升级至 `v0.0.22`，并准备执行推送自动触发 Github CI。

## 关键技术点
- `curl` 解析后端响应时，必须对齐最新的 Swagger/Go 结构体声明（`ServiceDetail` 中 `State` 序列化对应的键名为 `status`）。
- `restart` 策略中的嵌套 YAML 结构要遵从反序列化的标准层级声明，不能使用下划线合并键名。

## 遗留事项
- 无。测试结果均顺利通过。

## Docker SYS_PTRACE 验证与端口探测降级清理

### 触发原因

Docker `cap_add: SYS_PTRACE` 已验证生效，据此收敛端口探测逻辑，移除不再需要的多层降级扫描。

### 完成要点

- 删除端口探测中的 UID、cmdline、`ss`、`netstat` 及命令扫描降级。
- 仅保留受管 PID 进程树的 fd socket inode 精确匹配。
- 修改文件：
  - `internal/api/port_collector.go`
  - `internal/api/port_collector_test.go`
  - `internal/api/resource_handler.go`
  - `internal/api/service_handler.go`
- 已完成验证且均通过：
  - `go build ./...`
  - `go vet ./...`
  - `go test ./internal/api/... -count=1`
  - `go test ./... -count=1`

### 关键技术点

- Docker 容器配置 `cap_add: SYS_PTRACE` 后，可读取受管进程树的 fd 链接，并通过 socket inode 进行精确端口归属匹配。
- 移除基于 UID、命令行和外部命令的模糊降级，避免端口归属误判。

### 遗留事项与部署要求

- 容器必须配置 `cap_add: SYS_PTRACE`，否则端口列表可能为空。

## auto-create-users 默认启用与生命周期前移

### 触发原因

需确保 Docker 环境中 `ALLID` 指定的系统用户在自启动服务启动前完成创建，并补充脚本幂等行为验证。

### 完成要点

- `docker-compose.yml` 增加 `ALLID="abc,claw"`。
- `auto-create-users` 默认改为 `enabled: true`。
- 生命周期触发时机由 `post_ready` 改为 `pre_start`，保证自启动服务启动前创建用户。
- 保留 `id` 用户存在判断，已有用户跳过创建。
- 新增隔离 mock 测试，验证已有用户 `existing` 被跳过、`abc`/`claw` 被创建，以及重复用户只创建一次。
- 修改文件：
  - `docker-compose.yml`
  - `internal/cli/init_examples.go`
  - `internal/cli/init_test.go`
- 当前版本保持 `v0.0.27`。

### 验证结果

以下命令均已通过：

- `go build ./...`
- `go vet ./...`
- `go test ./internal/cli -run AutoCreateUsers -count=1`
- `go test ./internal/extension -count=1`

### 遗留事项与部署说明

- 已有初始化目录不会被模板自动覆盖，需手动同步 `auto-create-users` 配置与脚本，或重新初始化。
