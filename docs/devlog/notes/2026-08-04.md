### 关键技术点

- **smartdns 路径基准双重性**：
  - `cache-file` 基准 = 进程 CWD（service.yaml 未设 workdir 时 = 服务根目录）
  - `domain-set -file` / `ip-set -file` / `plugin` / `conf-file` 基准 = 配置文件所在目录（config/）
  - 故 `cache-file config/smartdns.cache` 与 `domain-set -file rules/xxx.txt` 路径基准不同但都能正确解析
- **SSH 空密码注入**：`SSH_ASKPASS=<script> SSH_ASKPASS_REQUIRE=force setsid -w ssh ...` 通过 askpass 脚本输出空密码，绕过交互式密码提示
- **dropbear -B 模式**：允许空密码登录，但要求 `/etc/shadow` 中密码字段为空（`NP` 状态）；账号锁定（`L` 状态）会拒绝
- **容器重启恢复**：`/etc/shadow` 在 overlay 文件系统，容器重启后 root 密码恢复，需重新 `passwd -d root`
- **环境变量相对路径**：supd 启动服务时 CWD=服务根目录（service.yaml 未设 workdir），故 env.yaml 中的 `TRANSMISSION_HOME=config` 等相对路径会被进程正确解析为 `<服务根>/config/`
- **扩展脚本的 fallback 模式可接受**：`${SUPD_SERVICE_DIR:-/etc/supd/...}`（shell）和 `tjs.env.SUPD_SERVICE_DIR || '/etc/supd/...'`（JS）是标准防御性编码，supd 运行时注入环境变量覆盖 fallback，绝对路径仅在手动调试时生效
- **transmission-updater wasm 路径**：candidate 列表含 `${serviceDir}/../../runtimes/`（相对路径，优先）和 `/etc/supd/runtimes/`（绝对路径，最后 fallback），设计合理

## 全配置路径绝对/相对路径统一支持

### 触发原因

上一轮仅覆盖 `workdir`，本次全面排查全局、服务和扩展配置的路径消费链，统一支持绝对路径和按所属配置根解析的相对路径。

### 完成要点

- 新增统一 `config.ResolvePath` 与 `core.ResolveCommandPath`：全局路径相对 `<baseDir>`；服务命令、workdir、readiness script 及服务扩展相对服务根；裸命令保留 PATH 查找。
- 全局 `env_files`、`extension_dirs`、配置 runtime 支持绝对/相对路径；discovery、watcher、CLI validate、热重载和 runtime provider 使用同一规则。
- 全局扩展 entry/CWD 统一为 `<baseDir>`，服务扩展 entry/CWD 统一为服务根；生命周期、按需、cron、重试及私有 env 路径完整传递。
- 扩展 entry 允许绝对路径，仍拒绝独立 `..` 路径段、shell 元字符和冗余路径组件；导入导出按最终配置根校验实际入口。
- 运行审计发现并修复 API 手动启动/重启 readiness 未完整传递服务根、服务级按需扩展 CWD、直接按需扩展 env 上下文等遗漏。
- `extension_dirs` 热修改会用新目录立即重扫，但 watcher 根集合需重启 supd 才持续监听，因此分类为需重启 supd。

### 严格运行测试与验证

- 使用 `/tmp/supd-path-runtime` 本地二进制验证相对/绝对服务 command、workdir、readiness script、runtime、extension_dirs、全局/服务扩展 entry 与 CWD。

#### 3. 生成器修复（3 个 bug）

- **regex 缺少 `/.../ ` 分隔符**：`make_config_block` 中 `assetPattern`/`versionRegex`/`remoteVersionFromTag` 直接输出 Python raw string，导致 JS 语法错误（`Unexpected token '\\'`）。修复：用 `/{pattern}/` 包装。
- **`${{service_id}}` 未替换**：模板中 `${{service_id}}` 经 Python format 后变为 `${service_id}`（JS 变量引用），导致 `ReferenceError: service_id is not defined`。修复：改为 `{service_id}`（Python 格式占位符），format 后直接内联服务名。
- **asset_pattern 与实际资产不匹配**：
  - backrest 实际资产名 `backrest_Linux_x86_64.tar.gz`（无版本号），原 pattern 期望 `backrest_<version>_Linux_x86_64.tar.gz`。
  - smartdns 实际资产名 `smartdns.1.2026.07.28-0446.x86_64-linux-all.tar.gz`（含连字符），原 pattern `[0-9.]+` 不匹配 `-`。修复：backrest 改为 `backrest_Linux_x86_64\.tar\.gz$`；smartdns 改为 `smartdns\.[0-9].*\.x86_64-linux-all\.tar\.gz$`。
