## 关键技术点

### R-06 回归问题根因
Go 类型断言对 typed nil 返回 `ok=true`：
```go
var nilMeta (*config.ExtensionMeta) = nil
old, ok1 := oldConfig.(*config.ExtensionMeta)  // ok1=true, old=nil
// old.Triggers 会 panic
```
解决方案：在函数入口做显式 nil 检查，而非依赖类型断言的 ok 返回值。

### 类型断言 nil 陷阱
- `interface{}` 为 typed nil（如 `(*T)(nil)`）→ 类型断言成功，但值为 nil
- `interface{}` 为 untyped nil（`nil`）→ 类型断言失败
- 防御：永远不要依赖类型断言的 ok 返回值来判断 nil，应在断言后显式检查指针

- **R-01 属实**：原实现按命令匹配后取首个进程；但“返回所有同名进程”会跨服务误计。改为 `NSpid` 精确映射，唯一候选才允许回退，多候选歧义拒绝猜测。

- **R-08 属实但生产不可达**：低成本 nil 防御合理，返回已初始化空 map，保持下游默认 10s/60s 停止语义。
