## 188 auto-create-users 扩展 bug 修复（13:15，仅改 188 运行脚本，未动仓库源码）
- 用户诉求：188 扩展报错 `adduser: unknown group 1000` / `unknown group 1001`，失败:2。要求"只修 188 上的扩展，不改源码"。
- **根因（两层）**：
  1. 旧脚本 `adduser` 分支用 `-G $gid`（传数字 gid 给 busybox `-G`）→ busybox `adduser -G` 要求**已存在的组名**，传数字 gid 直接报 `unknown group <gid>`。→ `abc`/`claw` 用户条目从未建出（`/etc/passwd` 无记录），但同名组被 `ensure_group` 建出了。
  2. 即便改用 `-g $gid`，busybox `adduser -g` **无效**（静默回落主组到 nogroup 65533，仍返回 0）。
- **正确修法（经 188 实机对比验证）**：busybox `adduser` 设主组**必须用 `-G <组名>`**（大写 G，传组名，组须先存在；`-g` 任何形式在 busybox 上无效）。`ensure_group` 已先 `addgroup -S -g $gid $user` 建好同名组，故 `adduser` 用 `-G $user`（=组名）即可。
- **实际改动（`/etc/supd/extensions/auto-create-users/run.sh`，仅一行 + 注释）**：
  - `opts="$opts -G $gid"` → `opts="$opts -G $user"`（先已 sed 试过 `-g $gid` 无效，最终定为 `-G $user`）。
  - 备份：`run.sh.bak.20260726b`（改前）、`run.sh.bak.20260726c`（改 `-G $gid`→`-G $user` 前）。
- **验证**：临时用户 acutest:9001:9001 实跑 → `uid=9001 gid=9001` 正确；再用真实 ALLID 跑 → `abc: uid=1000 gid=1000`、`claw: uid=1001 gid=1001` 均正确，`失败:0`，测试用户已清理。
